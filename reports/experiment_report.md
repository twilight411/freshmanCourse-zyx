# BIRD / Spider 基线与实验结果整理报告

整理人：朱雅轩。整理日期：北京时间 2026-11-17。已有实验记录日期：北京时间 2026-11-05。本次仅整理和复核现有材料，没有重新调用模型或重新执行基准数据库查询。

## 1. 任务范围与进度

已对 BIRD、Spider 2.0 做初步可行性分析，选择 BIRD Mini-Dev SQLite 开展首轮实验。Spider 2.0 目前只有调研材料，没有本仓库可核验的模型实验成绩。具体版本、访问条件和数据规模见 [调研原稿](benchmark_feasibility.md)。

`rsi-flow` 已在原工作区拉取 `dev_rsi` 分支、提交 `93cc223de5bc8f0510801796a46a8ae391725be9`，并有超长输入、分支与嵌套流程的占位方案。离线图校验通过，但 Java 测试曾因 `cc.eamon.open:auto-config:1.0.6` 下载返回 401 而阻塞。此部分尚未接入真实模型及 Text-to-SQL 数据集，不作为已完成实验提交。

## 2. 数据、基线和实验设置

- 数据：BIRD Mini-Dev 2026 SQLite，500 题、11 个数据库，题号 0–499。
- 标注 revision：`5b256b5a9c17478f06ed6912612e9a14d17065c8`。文件哈希及数据库来源见 [PROVENANCE](../data/PROVENANCE.md)。
- 基线：直接使用发布的固定 SQLite 推理提示词。
- 检查清单组：在同一提示词 `Output Format` 前增加 schema、键、粒度、空值、除法和日期等检查要求。
- 两组共用 `deepseek-flash`、temperature=0、thinking=disabled、max_tokens=4096，每组 500 条记录。推理代码不读取金标 SQL，金标只用于独立评分。
- 早期 20 题探索过检查清单，因此本轮属于探索性对比，不是预注册的独立验证。该清单并非收集到的人工反馈，也不是多 Agent 推理。

官方输出见 [baseline_official.txt](../experiments/pilot/runs/full_official_eval/baseline_official.txt) 和 [structured_official.txt](../experiments/pilot/runs/full_official_eval/structured_official.txt)。本地结果见 [grades.jsonl](../experiments/pilot/runs/full_official_eval/grades.jsonl) 和 [分组统计](../experiments/pilot/runs/full_official_eval/summary.md)。

本地统计：62 题由错变对、49 题由对变错，精确双侧 McNemar p=0.2546。排除 20 道调试题后，基线 198/480、检查清单组 209/480，p=0.3382。提高是正向线索，尚不足以证明稳定提升。

1000 条输出中 1 条无法抽取 SQL、4 条触及输出上限。基线生成 SQL 成功执行 481/500，检查清单组 478/500；500 条金标在本地评测中均执行成功。成功执行并不代表答案正确。

官方评分对预测与金标查询合计设置 30 秒超时；本地评分对每条查询分别设置 30 秒，另有结果行数上限，因此两者相差 1–2 题。原始记录提及官方复跑检查清单组曾为 222/500，但该复跑逐题产物未保存在当前提交包中，主表只采用可核验的首次官方汇总。配对统计来自本地评分，不能冒充官方配对统计。

## 4. 至少五类问题及证据

下表是现有评分日志可直接确认的失败类型；例子中的组别和题号可在 `grades.jsonl` 及对应模型输出中交叉查看。它是失败现象归类，不是互斥的语义根因标注，也不声称覆盖所有错题。

| 类型 | 可核验例子（题号从 0 开始） | 对后续实验的启发 |
|---|---|---|
| SQL 抽取失败 | q410 基线：`no SELECT or WITH statement found` | 明确输出契约，单独报告抽取失败率 |
| SQL 语法不完整或非法 | q20 检查清单组：`incomplete input`；q106 检查清单组：点号附近语法错误 | 区分截断、格式与生成语法问题；不能把所有语法错都归因于 token 上限 |
| 字段或别名引用错误 | q179 基线：`no such column: m.match_id`；检查清单组：`m.id` 不存在 | 结合 schema 做字段和别名核对；仍需人工检查字段本身还是别名作用域出错 |
| 表名引用错误 | q470 基线：`no such table: element` | 核对真实表名及 schema 对齐 |
| 查询执行超时 | q51 检查清单组：`query timed out after 30s` | 检查连接、中间结果与计算复杂度，并固定超时规则 |
| 提示词修改引起回归 | q1、q19、q21 等在基线正确、检查清单组错误 | 不能只展示改善样本；对称分析 62 题改善与 49 题回归 |

另外存在 SQL 执行成功却不匹配金标结果的情况。聚合粒度、连接、筛选条件、排序及数值语义是待逐题核查的候选原因，目前尚未完成这些语义根因的人工标签，不报告各类根因比例。

## 5. 局限与下一步

当前仅完成一个数据集、一个服务商模型别名的两种提示词对比。temperature=0 不能保证跨时间重复输出一致。检查清单改变了提示词内容和长度，不能把差异单独归因于某一种推理机制。

下一步优先核对改善/回归题，形成可审计的语义错误标签；在相同模型、数据和预算下加入执行反馈或数据库级知识，再进行独立验证。Spider 模型实验与 rsi-flow 实际运行应分别补齐证据，不将现有 BIRD 提示词成绩当作结构验证结果。
